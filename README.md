# Chronos-2 시나리오 모델 (chronos2_training)

기존 kNN 작업(`model_training`)은 **그대로 두고**, 같은 문제를 Chronos-2(Amazon의 시계열 파운데이션 모델)로 풀어 보는 별도 폴더입니다.
`model_training`의 파일은 읽기만 하고 수정하지 않으며, 결과와 모델은 이 폴더의 `results/`, `models/`에만 저장됩니다.

## 무엇을 하나
"앞으로 5거래일 동안 미국 10년 금리·원달러가 이만큼 움직이면, 코스피 5일 뒤 수익률의 하단 10% · 중앙 · 상단 90%는?"
기준시각(한국 거래일 오후 6시)과 충격 정의는 기획서·kNN과 같습니다.

## 입력과 출력

| 구분 | 내용 | 열 이름 |
|---|---|---|
| 예측 대상(타깃) | 코스피 **후행 5일 수익률(%)** 일별 시계열. 예측 5번째 단계의 값 = kNN의 정답(5일 뒤 수익률) | `kospi_ret_5d_pct` |
| 미래에 알려진 공변량 = **충격** | 미국 10년 금리 후행 5일 변화(bp), 원달러 후행 5일 변화(%). 5번째 단계의 값 = kNN의 충격 2개 | `us_treasury_10y_chg_5d_bp`, `usdkrw_ret_5d_pct` |
| 과거 공변량 | 입력 구성(아래)에 따라 0~15개 | |
| 컨텍스트 | 기준일 포함 최근 L거래일 (기본 512) | `--context` |
| 출력 | 1~5일차 각각의 분위수. 쓰는 값은 5일차 하단 10% / 중앙 / 상단 90% | `pred_ret_q10/q50/q90` |

- 사용자는 5일 **누적** 충격(예: 금리 +20bp)만 고릅니다. 모델에는 일별 경로가 필요하므로 `--shape`(기본 `linear`: 5일에 걸쳐 일정하게)로 풀어서 넣습니다. 5일차 값은 입력한 충격과 정확히 같습니다.
- BASE = 충격 0, STRESS = 사용자 충격. 같은 시장 상태에서 두 번 계산해 비교합니다.
- 거래일에는 주말·휴일이 빠져 있어서, Chronos-2의 "빈 날짜 없음" 조건에 맞추려고 거래일 번호를 하루 간격 가상 날짜로 바꿔 넣습니다.

**이 모델이 내지 않는 것**: "5일 중 최저 수익률", "5일 뒤 −5% 이하 확률". 출력이 날짜별 분위수라서 5일 경로 전체의 최저값은 알 수 없습니다. 이 두 값은 기존 kNN 쪽을 함께 쓰세요.

## 세 가지 구성

`학습표_구조정리.xlsx`의 "컬럼 정의"(28행)에서 모델 입력은 **20개**(시장 상태 18 + 가정 충격 2)입니다. 나머지는 식별(date·split 등)과 정답 열입니다.

| 구성 | `--variants` | 쓰는 열 | 학습 |
|---|---|---|---|
| **1. 기존 입력 전부** | `all` | 타깃 1 + 충격 2 + 과거 공변량 15 (= 시장 상태 18개 전부) | 없음 (제로샷) |
| **2. 직접 고른 열** | `select` | 타깃 1 + 충격 2 + 과거 공변량 5 (`vix`, `kospi_vol_20d_ann_pct`, `kospi_ret_20d_pct`, `kosdaq_ret_5d_pct`, `kospi_foreign_flow_5d_z`) | 없음 (제로샷) |
| **3. 더 나은 학습법** | 제로샷 valid 성적이 가장 좋은 `full` | 과거 3 + 충격 2 | LoRA 파인튜닝(검증으로 학습 시점 선택) + 구간 보정 |
| (참고) 처음 구성 | `full`, `shock_only`, `no_cov` | 과거 3 + 충격 2 / 충격만 / 코스피만 | 없음 |
| (참고) 충격 효과 분리용 | `past_only`(B), `rate_only`(C), `fx_only`(D) | 과거 3 / 과거 3 + 금리 충격 / 과거 3 + 환율 충격 (`full` = E) | 없음 |

제로샷 valid 결과(아래 표)는 `full` > `select` > `all` 순이었습니다. 열을 늘릴수록 좋아지지 않아서 구성 3의 기본은 `full`로 정했습니다.

- 월 단위 지표(물가·실업률)는 설계서대로 2개월 시차가 이미 적용된 값입니다. 맨 끝 두 구간(2025-12~2026-01, 63칸)의 빈칸만 마지막 확정값으로 이어 붙였습니다.

### 구성 2에서 열을 고른 근거
학습 기간(2001~2018)만으로, 충격 2개로 설명하고 남은 5일 수익률과 각 열의 순위상관을 봤습니다 (valid·test 자료는 사용하지 않음). 독립 구간이 약 880개라 대략 |상관| 0.067 이상이면 우연이 아닐 가능성이 있습니다.

- **방향**(남은 수익률의 부호)과는 어떤 열도 0.065를 넘지 못했습니다. 수익률의 방향은 이 열들로 거의 예측되지 않고, 열들은 주로 **변동 폭**(범위의 너비)에 영향을 줍니다.
- **변동 폭**과의 상관(절댓값 기준)에서 뽑은 열:

| 열 | 상관 | 선택 | 이유 |
|---|---|---|---|
| `kospi_vol_20d_ann_pct` | +0.34 | ○ | 변동성 상태 |
| `vix` | +0.26 | ○ | 변동성 상태 |
| `kosdaq_ret_5d_pct` | −0.11 | ○ | 주변 시장의 최근 움직임 |
| `kospi_foreign_flow_5d_z` | −0.09 | ○ | 외국인 수급 |
| `kospi_ret_20d_pct` | −0.09 | ○ | 기존 구성 유지 |
| `kr_treasury_3y`, `bok_base_rate`, `us_treasury_10y`, `kr_cpi_yoy_pct` | +0.26~+0.33 | × | 수준값이라 변동성이 컸던 2000년대 같은 "시대"와 함께 움직여 생긴 상관일 수 있고, 최근 512일 창 안에서는 거의 변하지 않음 |
| `usdkrw`(수준), `us_unemployment_change_1m_pp`, `us_cpi_yoy_pct` | +0.12~+0.14 | × | 같은 이유, 월 단위 지표 |
| `kospi_institution_flow_5d_z` | +0.07 | × | 외국인 수급과 겹치고 우연 수준 경계 |
| `vix_chg_5d_pt`, `us_curve_slope_10y2y_pp` | +0.06, +0.05 | × | 우연 수준 |

이것은 가벼운 사전 선별일 뿐이고, 최종 판단은 valid 성적(`compare.py`)으로 합니다. **결과: 이 선별한 5개(`select`)도 처음의 3개(`full`)보다 낫지 않았습니다** (pinball 0.656 vs 0.649). 변동 폭과 상관이 있다는 것과, 이 모델이 그 열을 써서 예측을 개선한다는 것은 별개였습니다.

### 구성 3: "더 나은 학습법"이 의미하는 것
1. **LoRA 파인튜닝**(`finetune.py`): 모델 전체가 아니라 작은 보조 가중치만 학습합니다. 서로 겹치는 5일 정답이 많아 실질 표본이 약 1,200개뿐이라 과적합을 막기 위해서입니다.
2. **검증으로 학습 시점 고르기**: 자료 끝 2년(2017~2018)은 학습에서 빼 두고, 5거래일마다 하나씩 시험 문제(약 97개)로 쓰면서 100스텝마다 오차를 재고 가장 좋은 시점의 모델을 저장합니다. 평가 구간(2019~)은 이 과정에 쓰이지 않습니다.
3. **구간 보정**(`calibrate.py`): 제로샷은 범위가 좁아 "80% 범위"가 실제로는 약 71%만 맞았습니다. 앞 기간(2019~2020)으로 하단·상단 이탈이 각각 10%가 되는 배율을 구하고, 보지 못한 뒤 기간(2021~2022)에서 실제로 좋아졌는지 확인합니다. 방식은 세 가지(전체 배율 / **하단만** / VIX 구간별)이며 아래 "구간 보정을 해 본 결과"를 보고 고릅니다.
4. **설정은 valid로만 고름**(`sweep.py`): 학습률 × 스텝 후보를 차례로 학습·채점해 한 표로 비교합니다.

## 폴더
```
chronos2_training/
  README.md  requirements.txt
  src/
    common.py            공통: 데이터 불러오기, 입력표 만들기, 예측 호출, 지표, 구간 보정 계산
    selfcheck.py         데이터 준비 점검 (chronos 없이도 실행됨)
    evaluate.py          제로샷/파인튜닝 모델 채점 (kNN과 같은 행·정답·지표)
    compare.py           results/ 의 모든 평가 결과를 한 표로 비교
    finetune.py          파인튜닝 (LoRA, 검증으로 학습 시점 선택)
    sweep.py             파인튜닝 설정 여러 개를 학습·채점해 비교
    calibrate.py         구간 보정 (앞 기간으로 배율 → 뒤 기간에서 확인)
    predict_scenario.py  BASE/STRESS 계산, 반응 곡선
  results/  models/      실행하면 생김
```

## 실행 순서
**1) 점검** — `python src/selfcheck.py`  (모든 항목이 [통과]여야 합니다)

**2) 제로샷으로 구성 1·2를 valid에서 채점** (학습 없음, 구성당 몇 분~수십 분)
```
python src/evaluate.py --split valid --variants select --context 512
python src/evaluate.py --split valid --variants all --context 512 --batch-items 16
```
- 먼저 속도 확인: 끝에 `--limit 60` (성능 비교에는 쓰지 마세요).
- `all`은 열이 많아 메모리를 더 씁니다. 부족하면 `--batch-items`를 8~16으로 줄이세요.
- 이미 돌린 `full`, `no_cov` 결과도 `results/`에 남아 있어서 아래 비교에 함께 나옵니다.

**3) 한 표로 비교** — `python src/compare.py`
이름은 `모델|입력 구성|컨텍스트`입니다. `all`, `select`, `full`, `no_cov`의 pinball·포함률을 나란히 봅니다.
충격만 넣은 `shock_only`도 돌려 두면 "충격이 도움인지, VIX가 도움인지"를 가를 수 있습니다: `python src/evaluate.py --split valid --variants shock_only --context 512`

**4) 구성 3: 파인튜닝** — 제로샷에서 가장 좋았던 `full`로
```
python src/finetune.py --variant full --tag m3_full
python src/evaluate.py --split valid --model models/m3_full/finetuned-ckpt --variants full --context 512
python src/compare.py
```
설정을 여러 개 비교하려면: `python src/sweep.py --variant full --dry`로 명령을 확인한 뒤 `--dry` 없이 실행합니다 (오래 걸림).

**5) 구간 보정** — 제로샷 또는 파인튜닝 모델의 valid 예측 파일에 적용
```
python src/calibrate.py --pred results/eval_valid_amazon_chronos-2_full_L512_predictions.csv results/eval_valid_m3_full_full_L512_predictions.csv
```
표의 `원래`와 `보정` 행을 비교합니다. 80% 포함률이 0.80에 가까워지고 pinball이 같거나 낮으면 보정이 통한 것입니다. 연도별 성적도 함께 나와서 어느 해에 범위가 모자랐는지 볼 수 있습니다.

**6) 설정 확정 후 test를 한 번만** (`--final`)
```
python src/evaluate.py --split test --final --model amazon/chronos-2 --variants full --context 512 --calib results/calib_<이름>.json --calib-mode lower
```
- `--calib-mode`는 `global`(전체 배율, 기본) / `lower`(하단만) / `by_vix`. valid에서 고른 방식 하나만 씁니다.
- 파인튜닝 모델이면 `--model models/m3_full/finetuned-ckpt`. 최종용으로 `finetune.py --upto 2022`로 다시 학습할 수도 있지만, 보정 배율은 2018까지 학습한 모델의 valid 예측으로 구한 것이라 다시 학습한 모델에는 꼭 맞지 않을 수 있습니다. 바꾸지 않고 `--upto 2018` 모델을 그대로 쓰는 쪽이 보정과 일관됩니다.
- test 결과를 보고 다시 고르지 않습니다 (kNN 때와 같은 원칙). 표에 기존 kNN 행이 함께 나옵니다.

**7) 시나리오 계산** — `python src/predict_scenario.py --variant full --rate 20 --fx 0 --calib results/calib_<이름>.json --calib-mode lower` (`--date 2022-09-26`, `--curve` 반응 곡선)

## 충격 효과를 떼어 보고 결과를 검증하기 (감사)
지금의 점수는 **그 5거래일에 실제로 일어난 금리·환율 변화를 알려 주고** 코스피 분포를 맞히게 한 조건부 진단입니다(사전 예측 아님). 충격 정보의 순수 기여는 아래 비교로 봅니다. 모두 같은 983일·같은 정답·같은 모델/문맥 길이입니다. 충격을 "빼는" 구성은 열 자체를 제거한 것이고 0으로 채운 것이 아닙니다.

| | 구성(`--variants`) | 입력 |
|---|---|---|
| A | `no_cov` | 코스피 기록만 |
| B | `past_only` | A + 과거 3 (`vix`, 코스피 변동성, 코스피 20일 수익률) |
| C | `rate_only` | B + 금리 충격 |
| D | `fx_only` | B + 환율 충격 |
| E | `full` | B + 금리·환율 충격 |

```
python src/evaluate.py --split valid --variants past_only,rate_only,fx_only --context 512
python src/evaluate.py --split valid --variants full --context 512 --zero-shock --tag zero   # 충격 있음(실제)  vs  충격 열은 있으나 0 으로 채움  vs  열 없음
python src/compare.py --ref past_only          # E 대 B 등 짝지은 차이와 95% 구간
python src/audit.py                            # 날짜별 원자료·연도별·분위수별·사건 수·예시 → results/audit/
```
- `evaluate.py`는 실행할 때마다 `*_runinfo.json`에 모델 revision, 라이브러리 버전, 입력 설정을 남깁니다 (알 수 없으면 "미확인").
- `compare.py --ref`의 구간은 같은 날짜의 두 모델을 함께 뽑는 20거래일 블록 부트스트랩(2,000회, 시드 0)입니다.

## 결과 읽는 법
- **pinball이 낮고 skill_vs_M1이 클수록** 좋습니다. 95% 구간(`ci_vs_M1`)이 0을 넘어야 "확실히 낫다"입니다.
- **80% 포함률**은 0.80에 가까울수록, 하단·상단 이탈은 각각 0.10에 가까울수록 좋습니다. 100%에 가까운 것은 좋은 게 아니라 범위가 너무 넓은 것입니다. 너무 좁거나(포함률 낮음) 너무 넓지(width80 큼) 않은지 함께 보세요.
- `coverage80_vix_high`는 시장이 불안한 날의 포함률입니다. 스트레스 테스트에서는 이쪽이 특히 중요합니다.
- 독립인 구간은 행 수의 약 1/5입니다(5일 정답끼리 4일이 겹침). 작은 차이는 우연일 수 있습니다.
- `full`이 `no_cov`보다 확실히 낫지 않다면, 충격 공변량이 이 모델에서는 쓸모가 없다는 뜻입니다. `predict_scenario.py --curve`로 충격을 바꿨을 때 결과가 말이 되게 움직이는지도 확인하세요.
- 평가 기본값(`--path ramp`)은 충격 **총량 2개만** 알려 주는 조건이라 kNN과 같은 정보량입니다. `--path realized`는 실제 일별 경로를 주는 더 유리한 조건이므로 비교용으로만 쓰세요.

## 한계
- valid 기준선(과거 분포, 변동성 스케일)은 2001~2018 고정 학습입니다. kNN 1단계의 연도별 재학습과는 다릅니다.
- 파인튜닝 데이터는 서로 겹치는 5일 구간이 많아 실질 표본이 약 1,200개뿐입니다. 스텝을 많이 돌리면 과적합하기 쉽습니다.
- 제로샷 모델이 사전 학습에서 어떤 자료를 봤는지는 공개된 범위 밖이라, 2019~2022 시장이 거기에 포함되지 않았다고 확신할 수는 없습니다. 최종 판단은 test를 한 번만 채점해서 합니다.
- 2026년 7월 현재 시장은 과거 범위를 벗어난 변동성입니다(kNN과 같은 한계). 충격을 바꿔도 결과가 거의 안 변할 수 있습니다.
- 결과는 과거 자료에서 배운 조건부 관계이며 충격 하나의 인과효과나 미래를 보장하는 값이 아닙니다.

## 이 코드의 점검 상태
- **실제 Chronos-2로 확인됨 (사용자 컴퓨터)**: `full`·`select`·`all`·`no_cov` 구성, 컨텍스트 512의 valid 전체 채점(`predict_df` 호출 포함).
- **실제 예측 파일로 확인함**: `calibrate.py`(전체 배율·하단만·VIX 구간별, 연도별 표)를 실제 valid 예측 3종에 적용.
- **실제 데이터로 확인함**: 타깃·충격 정의가 기존 학습표와 정확히 일치, 지표 계산이 kNN model_card와 같은 숫자, 모든 입력 구성의 날짜 간격, 파인튜닝 검증 시계열이 기준일의 정답·충격과 정렬됨, 구간 보정이 설계대로 이탈률을 10%로 맞춤.
